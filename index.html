1. The idea

MAX & MIN

Two players alternate. MAX picks the move with the highest utility, MIN picks the lowest. Minimax assumes both play perfectly.

Backing up values

Leaves get a utility from the game. Each internal node takes the max (MAX node) or min (MIN node) of its children. The root value is the guaranteed outcome.

Alpha-Beta

Keep α (best MAX can already guarantee) and β (best MIN can already guarantee). When α ≥ β the rest of that node's children cannot change the result, so they are pruned. Same answer, fewer nodes.

Cost

Minimax visits O(bd) nodes. Alpha-Beta with perfect ordering needs about O(bd/2), so it can search twice as deep. Real games use a depth limit plus a heuristic evaluation.

Pseudocode

function ALPHABETA(node, α, β):
  if node is terminal: return utility(node)
  if node is MAX:
    v = -∞
    for child in children(node):
      v = max(v, ALPHABETA(child, α, β))
      α = max(α, v)
      if α ≥ β: break      # β cutoff
    return v
  else:
    v = +∞
    for child in children(node):
      v = min(v, ALPHABETA(child, α, β))
      β = min(β, v)
      if α ≥ β: break      # α cutoff
    return v

Python

def minimax(node, maximizing):
    if node.is_terminal():
        return node.utility
    vals = (minimax(c, not maximizing)
            for c in node.children)
    return max(vals) if maximizing else min(vals)

def negamax(node, color):   # color = +1 / -1
    if node.is_terminal():
        return color * node.utility
    return max(-negamax(c, -color)
               for c in node.children)
